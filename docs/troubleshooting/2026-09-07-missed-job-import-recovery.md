# 9월 4일 채용공고 누락 복구와 재발 방지

## 현상

2026년 9월 4일 세 파티션 33건은 GitHub handoff까지 도착했지만 통합 검증이 enum 11개를 허용하지
않아 게시 전에 중단됐다. 운영 D1의 마지막 성공 포인터는 9월 3일 수집 run에 머물렀다. 9월 7일
일일 Slack 실행은 이미 DB에 있던 후보 15건을 모두 과거 발송 이력과 같은 source로 억제해 채용
공고 0건을 만들었다.

## 핵심 원인

1. 수집기가 의미는 같은 비정규 enum 표현을 만들었지만 canonical 별칭 표에 없었다.
2. 보호된 게시 API의 복구 기간이 하루뿐이어서 주말을 지난 정상 원본을 재처리할 수 없었다.
3. 늦은 복구 bundle에 이미 마감된 공고가 하나라도 있으면 전체 bundle이 거부됐다.
4. `포스코그룹` 같은 회사명 토큰과 `연구원`을 세부 직무로 해석해 같은 캠페인을 신규로 볼 수 있었다.
5. jobs-only 스냅샷 조회가 상시채용도 포함해 일일 알림 정책과 달랐다.

## 개선

- 실제 관측된 9월 4일 enum 표현을 canonical enum으로 명시적으로 매핑했다. 알려지지 않은 값은 계속
  fail-closed한다.
- 원본 `targetAsOfDate`와 checksum을 유지한 채 최대 7일 안에서만 복구하도록 경계를 확장했다.
- 모든 원본 행의 식별자와 행 수를 먼저 검증한 뒤, 복구 시점에 이미 마감된 행만 INSERT 대상에서
  제외하고 `skippedExpired`로 계수한다.
- 회사명 뒤의 `그룹` 표현과 일반적인 `연구원` 토큰을 역할 식별자에서 제거해 포괄 공고와 세부 공고를
  같은 캠페인으로 판정한다.
- jobs-only 스냅샷도 `rolling=0`, 비어 있지 않은 미래 `deadline_at` 조건을 사용한다.
