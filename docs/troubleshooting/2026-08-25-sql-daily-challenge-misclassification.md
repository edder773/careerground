# 오늘의 알고리즘 문제에 SQL 문제가 노출된 분류 오류

## 현상과 재현 기준선

오늘의 알고리즘 Lv. 1 자리에 `과일로 만든 아이스크림 고르기`가 노출됐다. 동일한 로컬 catalog와 D1 호환 runtime에서 확인한 수정 전 분류는 전체 427개 중 알고리즘 365개, SQL 62개였다. 프로그래머스 원문에서 SQL 작성을 요구하는 다음 네 문제가 `ALGORITHM`으로 저장돼 있었다.

- 132201: 12세 이하인 여자 환자 목록 출력하기
- 133024: 인기있는 아이스크림
- 133025: 과일로 만든 아이스크림 고르기
- 151136: 평균 일일 대여 요금 구하기

## 원인

추천 쿼리는 이미 `track = 'ALGORITHM'`과 정확한 레벨을 조건으로 사용했다. 그러나 초기 catalog의 `track` 값이 잘못됐고, 후속 SQL 분류 migration의 명시적 ID 목록에도 위 네 ID가 빠져 있었다. 따라서 쿼리는 잘못 분류된 레코드를 정상 알고리즘 후보로 판단했다.

또한 이미 만들어진 오늘의 문제 행은 슬롯 번호만 존재하면 재사용했고, 관리자 수동 재선정 API도 레벨만 확인해 SQL 트랙 유입을 막지 못했다.

## 수정

1. 네 문제의 원본 catalog와 D1/PostgreSQL migration 분류를 `SQL`로 정정했다.
2. catalog migration 생성기가 `track`을 INSERT와 UPSERT 모두에 반영하도록 수정했다.
3. 오늘의 문제 조회 시 슬롯별 불변조건을 검사한다. Lv. 1·2는 알고리즘, SQL 슬롯은 SQL Lv. 3~4가 아니면 잘못된 행과 연결된 참여 행을 제거하고 정상 후보를 다시 선정한다.
4. Slack 전용 Lv. 3 조회는 `ALGORITHM / Lv. 3`을 SQL 자체에서 강제한다.
5. 관리자 수동 재선정은 활성 `ALGORITHM`이면서 해당 슬롯과 같은 레벨인 문제만 허용하며, 화면 후보도 알고리즘 Lv. 1로 제한한다.
